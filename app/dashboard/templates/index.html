A REPEATABLE, SAFE WORKFLOW

Setup & test

Connect a watched folder, inspect its files, then test detection.

1. Monitoring scope

Configured folders:

For Docker, the host folder data/sandbox is mounted as /sandbox. The five department folders under data/sensitive-lab are mounted under /sensitive-lab: Finance, Human Resources, Customer Data, Legal and Backups. Other VM folders are outside this monitor.

To monitor another folder locally, stop the service and start it with a validated watch path: 

python -m app.main --config config.yaml --watch /absolute/path/to/folder

Path changes require a restart. Do not run a second monitor on the same database.

2. Local administrator access

Read views need no login. Scans, report generation and settings changes require your local token.

Kept only in this page’s memory. Never saved in browser storage.

Inventory existing files

Reads current files without modifying them. Inventory does not manufacture an attack or raise the live burst score.

3. Observe a controlled test

01 · Ordinary activity

Create a few text files and confirm events appear.

python scripts/simulate_activity.py --profile benign
02 · Suspicious pattern

Creates 50 new files, writes random bytes, then renames them to .locked. 

python scripts/simulate_activity.py --profile burst
03 · Investigate

Open Incidents. Inspect the peak, affected files and evidence; generate both reports.

Run these commands from the project directory on the host with the virtual environment activated. Each run uses a new exclusive folder and never selects existing user files. Random-content generation is not encryption; a .locked suffix does not prove ransomware. Wait one detection window between independent tests.
